# Оспаривание сделок

<https://bashmakak.github.io/sdelkospar/>

Конструктор заявлений об оспаривании сделок должника для арбитражного
управляющего. Вы один раз вводите сведения о деле и сделке, отвечаете на
несколько вопросов, отмечаете нужные блоки — и получаете готовое заявление
в DOCX или PDF.

**Никакого ИИ.** Какие обстоятельства есть в деле и какие блоки включать в
заявление, решает человек. Приложение отвечает за рутину: подстановку
реквизитов, условные поля, порядок разделов, нумерацию приложений и выгрузку.

## Как пользоваться

Открыть `dist/Оспаривание сделок.html` двойным кликом. Всё.

Файл самодостаточный: шрифт, шаблоны и вся логика встроены внутрь. Ни сервера,
ни интернета не требуется. **Данные никуда не отправляются** — дела хранятся
в вашем браузере, поэтому реквизиты должников и контрагентов не покидают
устройство.

Файл можно скопировать на флешку, переслать коллеге, положить на рабочий
стол — он останется работоспособным.

## Путь пользователя

```text
Новое дело → реквизиты → сделка → тип объекта → стороны →
несколько вопросов → выбор блоков → готовое заявление → DOCX / PDF
```

Ключевой принцип: **одни данные вводятся один раз**. Реквизиты дела и должника
подставляются во все заявления внутри дела, контрагент выбирается из
участников дела, а не набирается заново.

## Три документа по одной сделке

По сделке готовится не один документ, и данные у них общие — вводятся один раз:

* **заявление об оспаривании сделки**;
* **ходатайство об отсрочке уплаты государственной пошлины** — сумма и её
  расчёт подставляются из карточки сделки;
* **предложение о возврате в конкурсную массу** — досудебный порядок по
  пункту 4 статьи 20.3 Закона о банкротстве, на который потом ссылается само
  заявление.

Каждый собирается своим набором блоков: у ходатайства своя просительная часть,
у предложения — своя шапка (письмо адресуется ответчику, а не суду). Порядок
блоков задан видом документа, поэтому общие блоки — шапка, приложения,
подпись — стоят в каждом на своём месте.

Ходатайству нужны два поля, которых нет в заявлении: остаток на счетах
должника и перечень банков, куда направлялись запросы. Они заводятся в
карточке дела.

## Импорт печатной формы

Рабочая система управляющего выгружает по делу «печатную форму» — DOCX, где
реквизиты суда, должника, управляющего и процедуры уже подставлены. Кнопка
**«Загрузить печатную форму»** читает такой файл и заводит из него дело:
суд и его адрес, номер дела, дата принятия заявления о банкротстве, судебный
акт и процедура, ФИО должника с датой и местом рождения, ИНН, СНИЛС и адресом
регистрации, ФИО управляющего с ИНН, СНИЛС и регистрационным номером, СРО с
ОГРН и адресом, а если графа заполнена — и ответчик со своим адресом.

Отдельно вытаскивается ФИО должника в родительном падеже: строку
«…управляющий имуществом должника Абрамовой Зарият Руслановны» формы печатают
готовой, и это надёжнее любого склонения по правилам. Для дела, заведённого
руками, падеж выводится сам — у людей; наименование организации не
склоняется, склоняется только организационно-правовая форма
(«Общества с ограниченной ответственностью «Ромашка»»).

Файл читается в браузере: `.docx` — это ZIP с XML, распаковку берёт на себя
встроенный в браузер `DecompressionStream`. Никаких библиотек и никакой
отправки файла на сервер.

Разбор снисходительный: формулировки в формах гуляют от суда к суду, поэтому
каждое поле ищется своим правилом, ненайденное остаётся пустым, а окно импорта
показывает и распознанное, и то, что придётся дозаполнить руками.

## Государственная пошлина

Считается по статье 333.21 НК РФ в редакции с 09.09.2024 и раскладывается на
слагаемые:

* требование имущественного характера по цене иска — подпункт 1 пункта 1
  (шкала для организации или для физического лица);
* требование о признании сделки недействительной — подпункт 2 пункта 1
  (15 000 ₽ для физических лиц, 50 000 ₽ для организаций);
* обособленный спор в деле о банкротстве — 50 % по подпункту 9 пункта 1.

Расчёт показывается по шагам: сумму под заявлением подписывает человек, и он
должен видеть, из чего она сложилась. Есть поле для своей суммы, если суд
считает иначе.

**Формула сверена по четырём готовым заявлениям.** При цене иска 205 000,
415 150 и 933 114 ₽ расчёт сходится до копейки (15 125, 20 379 и 33 328 ₽).
В четвёртом (1 418 640 ₽) в шаблоне стоит 33 779,50 ₽ — это ровно половина
имущественной части без 7 500 ₽ за требование о недействительности; для такого
случая галочка снимается. Ставки лежат данными в `src/data.js`: меняются они
законом, и править их должно быть можно, не разбираясь в остальном приложении.

## Таблицы по кредитному отчёту

К делу прикладывается PDF-отчёт ОКБ или «Кредистории» — тот же разбор, что и в
[анализаторе отчётов](https://github.com/bashmakak/okb-payment-analyzer),
файл `src/parser.js` перенесён без правок. Из отчёта строятся две таблицы,
которые вставляются прямо в текст заявления:

* **возникновение просроченной задолженности** — по каждому обязательству дата,
  с которой считается просрочка, её размер, длительность и погашена ли она;
* **просроченная задолженность на дату сделки** — основной долг, просрочено,
  с какого числа и сколько дней, с итогом по всем кредиторам.

Даты берутся из поля отчёта «просрочка с», а не из даты снимка задолженности:
снимки редкие, и по ним просрочка «появляется» на месяц-другой позже, чем
возникла.

Выводов приложение не делает. Момент неплатёжеспособности — правовая
квалификация, и её даёт управляющий; таблица показывает факты и самую раннюю
непогашенную просрочку, а формулировку пишет человек.

Отчёт хранится в деле в урезанном виде — только поля, нужные таблицам. Иначе
одно дело заняло бы весь `localStorage`.

## Что внутри

* **Дела.** Суд, номер, процедура, дата возбуждения, судебный акт, должник,
  арбитражный управляющий. Пустые поля управляющего берутся из профиля.
* **Стороны.** Юридическое лицо, физическое лицо, ИП — у каждого свой набор
  полей. Сторона заводится один раз и переиспользуется в сделках дела.
* **Сделки.** Тип, даты, номер, сумма, предмет, объект, исполнение,
  обстоятельства, документы. Форма динамическая: поля объекта зависят от того,
  недвижимость это, транспорт, деньги или иное; вопрос о встречном исполнении
  раскрывает разные наборы полей для «частично» и «нет».
* **Обстоятельства.** Пять вопросов «да / нет» — неравноценность, вред
  кредиторам, заинтересованность, предпочтение, осведомлённость. Ответ «да»
  включает соответствующий блок заявления и открывает уточняющие поля,
  «нет» — выключает блок.
* **Конструктор.** Слева список блоков: включить, выключить, перетащить,
  раскрыть и отредактировать текст. Справа — предпросмотр, который
  перестраивается на каждое изменение. Незаполненные переменные подсвечены
  прямо в тексте.
* **Проверка.** Обязательные поля и логические ошибки: дата исполнения раньше
  даты договора, сумма сделки расходится с суммой платежа, включён блок
  неравноценности без стоимостей встречного исполнения.
* **Приложения.** Список собирается из документов сделки, нумерация
  пересчитывается при любом изменении.
* **Версии.** Снимок состава блоков и текста; версии можно смотреть,
  восстанавливать и сравнивать построчно.
* **Копирование сделки.** «Создать на основе этой» переносит стороны, тип,
  обстоятельства и состав блоков всех документов — меняются только номер
  и даты. Полезно, когда однотипных сделок много.

## Шаблоны и переменные

Текст не захардкожен в интерфейсе. Каждый блок — это шаблон с переменными
вида `{{DEAL_DATE}}`, `{{DEBTOR_NAME}}`, `{{OBJECT_ADDRESS}}`. Реестр
переменных единый, кнопка «Вставить переменную» берёт список из него же.

```text
{{DEAL_DATE}} между {{DEBTOR_SHORT}} и {{COUNTERPARTY_SHORT}}
заключён {{DEAL_TYPE}} № {{DEAL_NUMBER}}.

  ↓

15 апреля 2025 года между ООО «Ромашка» и ООО «Василёк»
заключён договор купли-продажи № 15.
```

Суммы попадают в документ и цифрами, и прописью: `{{DEAL_AMOUNT}}` даёт
`8 400 000,00`, `{{DEAL_AMOUNT_WORDS}}` — «Восемь миллионов четыреста тысяч
рублей 00 копеек». Падежные формы статуса управляющего («конкурсный
управляющий» / «конкурсным управляющим») хранятся в справочнике, а не
выводятся правилами: склонение по правилам в русском языке всё равно даёт
осечки.

Условие показа блока записывается человекочитаемо:

```text
deal.unequal = true
deal.objectType = money AND deal.amount > 1000000
```

Разбирает их собственный мини-интерпретатор — сравнения, склеенные `AND` и
`OR`. `eval` не используется: выражение приходит из редактируемого шаблона,
исполнять оттуда код незачем.

Библиотека блоков правится в интерфейсе: у стандартных блоков меняется текст,
свои блоки создаются целиком. Правка текста прямо в конструкторе действует
только на одно заявление и библиотеку не трогает.

## Выгрузка

* **DOCX** собирается вручную, без библиотек: `.docx` — это ZIP из нескольких
  XML-файлов, и написать их дешевле, чем тащить в офлайновую страницу мегабайт
  стороннего кода. Поля по ГОСТ Р 7.0.97 (слева 30 мм под подшивку),
  Times New Roman 14 пт, полуторный интервал, номера страниц полем `PAGE`.
* **PDF** — печатью. Листы A4 раскладываются по фактическим высотам абзацев
  (браузер измеряет каждый), поэтому в предпросмотре и в файле одно и то же
  разбиение и одинаковые номера страниц.

## Где хранятся данные

В `localStorage` браузера, на этом компьютере. Сервера у приложения нет.
Кнопка «Резервная копия» выгружает всё в JSON и загружает обратно: так дела
переносятся на другую машину и переживают чистку кэша.

Файлы документов **не загружаются**: приложение хранит только реквизиты
(тип, номер, дата, примечание). Список приложений от этого собирается ничуть
не хуже, а персональные данные не оседают в хранилище браузера.

## Оформление

Палитра и приёмы общие с [анализатором отчётов
ОКБ](https://github.com/bashmakak/okb-payment-analyzer): алебастровый `#F1ECE6`
и тёплый грейж `#DDD5CD` — поверхности, угольный `#2B2D31` — текст, терракота
`#8D321F` — акцент, олива `#3A4027` — «готово». Плиточная раскладка,
градиентная плитка главного экрана, таблетки вкладок и кнопок, нумерованные
шаги. Имена классов совпадают с тем проектом намеренно — правку оформления
можно переносить между инструментами один в один.

Шрифт — **Onest** (SIL Open Font License 1.1), встроен в сборку как data:-URI.
Ссылка на CDN тут не годится: приложение должно работать с флешки без
интернета, и шрифт молча отвалился бы вместе со всей типографикой.

## Чего в первой версии нет

Регистрации и входа — приложение локальное, «профиль» это просто реквизиты
управляющего для подстановки. Загрузки файлов, массового импорта сделок из
Excel и общей библиотеки шаблонов организации: всё это требует сервера,
которого здесь сознательно нет.

Не делается и никакой автоматической юридической квалификации: ни анализа
судебной практики, ни поиска аффилированности, ни прогноза исхода дела.
Продукт должен быть предсказуемым.

## Размещение в сети

`dist/index.html` намеренно закоммичен — это позволяет разворачивать сайт без
сборки на стороне хостинга.

**GitHub Pages** публикуется из `dist` через `.github/workflows/pages.yml` при
каждом пуше в `main` — <https://bashmakak.github.io/sdelkospar/>. Один раз надо
зайти в Settings → Pages → Source и выбрать **GitHub Actions**: включить Pages
самим workflow нельзя, токену Actions это не разрешено.

**Render:** New → Static Site, подключить репозиторий, Publish Directory —
`dist`, Build Command оставить пустым. Настройки уже описаны в `render.yaml`.

Размещение безопасно: страница полностью клиентская, дела и реквизиты хранятся
в браузере посетителя и на сервер не попадают.

## Разработка

```bash
npm install      # pdf.js — единственная зависимость, нужна для разбора отчётов ОКБ
npm run font     # один раз: скачать и встроить Onest
npm run build    # пересобрать dist/
npm test         # стенд: 224 проверки, браузер не нужен
```

`src/fonts/onest.css` в репозиторий не коммитится, его создаёт `npm run font`;
без него сборка остановится с понятной ошибкой.

Слои разведены намеренно, чтобы менять шаблоны и добавлять новые виды
заявлений без переписывания логики:

* `src/data.js` — справочники, реестр переменных, ставки пошлины, склонение
  ФИО и библиотека блоков. Ни разметки, ни логики интерфейса: только данные.
* `src/import.js` — чтение DOCX и разбор печатной формы.
* `src/parser.js` — разбор PDF-отчёта ОКБ, перенесён из анализатора отчётов
  без правок.
* `src/okb.js` — выборка из отчёта: возникновение просрочек и долги на дату
  сделки.
* `src/store.js` — модель, шаблонизатор, условия, правила проверки, версии.
  Про DOM не знает — тот же код исполняется в Node-стенде.
* `src/doc.js` — ZIP и XML для DOCX, раскладка листов A4 для печати.
* `src/app.html` / `src/app.js` — интерфейс. Метки `@@FONT@@`, `@@DATA@@`,
  `@@STORE@@`, `@@DOC@@`, `@@APP@@` заменяются при сборке на встроенные скрипты.
* `test/run.mjs` — подстановка переменных, условия блоков, нумерация приложений,
  правила проверки, сравнение версий, ставки пошлины (по четырём реальным
  заявлениям), склонение ФИО, разбор печатной формы, выборка из кредитного
  отчёта и структура собранного DOCX (ZIP разбирается обратно, CRC сверяется,
  XML проверяется на сбалансированность). Отдельно сверяются метрики листа и
  скрытого контейнера для замера — если они разойдутся, текст молча полезет
  за обрез страницы.

  Настоящие печатные формы содержат персональные данные и в репозиторий не
  попадают: образец для теста собирается прямо в нём тем же ZIP-писателем,
  которым приложение делает DOCX.
